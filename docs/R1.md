# R1 — External verification: apus vs DeepSeek's official reference

R1 is the last open verification risk in `docs/STATUS.md`: every internal
gate (M0–M11) is green, but apus's tokens have never been compared against
DeepSeek's **official reference inference** for DeepSeek-V4-Flash-0731. The
reference needs a big CUDA host (the model is ~167 GB and its kernels need
CUDA + TileLang); apus runs on this Mac. This document is the complete
operator guide. No expertise assumed — follow the steps in order.

**The idea in one paragraph:** on a rented GPU host we run DeepSeek's own
inference code over an 8-prompt battery (`tests/r1b/prompts.json`) and record
the exact token ids it emits, plus, at every position, the runner-up margin
(how close the second-best token was). Back on this Mac we run apus on the
*same prompt token ids* and diff the streams. Because we feed apus the
reference's prompt ids directly, prompt-encoding differences cannot mask
model differences; prompt encoding itself is checked separately.

---

## 1. What you need to rent

- **GPUs: 4 × A100-80GB** (SXM or PCIe, one node; 4 × H100-80GB is also
  fine). The reference shards the model 4 ways (`model{0..3}-mp4`), each
  shard ~42 GB. Fewer, bigger GPUs (e.g. 2–3 × B200) would also work in
  principle but 4 is the tested configuration — stick with 4.
- **Disk: 400 GB free.** The HF download is ~167 GB and the converted
  checkpoint is another ~167 GB next to it.
- **RAM: 256 GB+ recommended** (the converter reads shards on CPU).
- **Image:** a recent PyTorch/CUDA image (Ubuntu 22.04/24.04, CUDA 12.x).
  If the image has no PyTorch, step 2 installs it.
- Expect **2–4 hours total** on the host (download dominates). Budget the
  rental accordingly.

## 2. Set up the host

```bash
# Python deps (reference-0731/inference/requirements.txt)
pip install "torch>=2.10.0" "transformers>=5.0.0" "safetensors>=0.7.0" \
            fast_hadamard_transform "tilelang==0.1.8"

# Weights (~167 GB; needs a free HF account + token: https://huggingface.co/settings/tokens)
huggingface-cli login        # paste your token
huggingface-cli download deepseek-ai/DeepSeek-V4-Flash-0731 \
    --local-dir /data/dsv4-0731-hf
```

## 3. Copy the R1 kit to the host

From this Mac, from the repo root (replace `HOST` and `/data` as appropriate):

```bash
rsync -avz tools/r1 HOST:/data/apus-r1/tools/
rsync -avz tests/r1b HOST:/data/apus-r1/tests/
rsync -avz reference-0731/inference HOST:/data/apus-r1/reference-0731/
rsync -avz reference-0731/encoding HOST:/data/apus-r1/reference-0731/
```

The script expects this exact relative layout (`tools/r1`, `tests/r1b`,
`reference-0731/{inference,encoding}` under one root) — it finds the other
pieces relative to itself.

## 4. Convert the weights (HF layout → mp layout)

On the host:

```bash
cd /data/apus-r1
python tools/r1/run_reference.py --convert-only \
    --hf-ckpt-path /data/dsv4-0731-hf \
    --ckpt-path    /data/dsv4-0731-mp4 \
    --world-size 4
```

This wraps DeepSeek's own `reference-0731/inference/convert.py` (expert
dtype `fp4`, per the official config). Expect **30–90 minutes** (it streams
167 GB through CPU memory). When it finishes, `/data/dsv4-0731-mp4` contains
`model0-mp4.safetensors` … `model3-mp4.safetensors` plus the tokenizer files.
After this point you may delete `/data/dsv4-0731-hf` if disk is tight.

## 5. Generate the goldens

```bash
cd /data/apus-r1
torchrun --nproc-per-node 4 tools/r1/run_reference.py \
    --ckpt-path /data/dsv4-0731-mp4 \
    --out /data/r1_goldens.json
```

- Model load: ~5–15 min. Then it prints one progress line per case and a
  token counter every 16 tokens.
- The battery is ~1,300 generated tokens total; on 4×A100 expect roughly
  **15–60 minutes** of generation.
- Per-case errors do not abort the run — a failed case is marked
  `"status": "failed"` in the output and the run continues.
- Optional smoke first: add `--max-tokens 4 --cases france_greedy` to verify
  the pipeline end-to-end in a few minutes before the full run.

**What the script does (so you can trust it):** it is a faithful batch-1
mirror of `reference-0731/inference/generate.py` — same model load, same
`torch.manual_seed(33377335)` at startup, same forward call pattern, same
in-forward sampling. Greedy cases (`"temp": 0`) use the reference's argmax
path: in 0731, sampling lives **inside** `model.forward`
(`model.py:939-946`: `temperature == 0 → logits.argmax(dim=-1)`), so there is
no RNG in greedy mode at all. The one sampled case (`france_sampled`,
temp 1.0) re-pins `torch.manual_seed(42)` immediately before the case; the
reference samples via a Gumbel-max trick and has **no top-p**. For every
generated position the script records the emitted token id, the top-1
(argmax) id, and the top1−top2 logit margin.

## 6. Bring the goldens home and compare

On this Mac:

```bash
scp HOST:/data/r1_goldens.json ~/Desktop/AI-PROJECTS/Apus/r1_goldens.json
cd ~/Desktop/AI-PROJECTS/Apus
.venv/bin/python tools/r1/compare.py --goldens r1_goldens.json
```

`compare.py` (stdlib only, no torch) starts `bin/apus serve` once and, per
case:

1. **Model comparison** — feeds apus the *golden prompt ids* verbatim and
   decodes with the case's parameters (greedy = temperature 0). Token ids are
   diffed position by position.
2. **Prompt-encoding checks** (cheap, no extra forward) — apus's chat and
   thinking encodings must reproduce the golden prompt ids byte-exactly.
3. **Raw end-to-end check** — one raw case is also run through apus's C
   tokenizer (`serve` "text" path; `apus run --prompt` always renders the
   chat template, so it cannot do raw) and must match the golden too.

Expect **1–2.5 hours** on this M1 (~1,300 tokens at 0.4–0.9 tok/s plus model
load). Close browsers/other apps first — free RAM is the #1 speed factor.
Useful flags: `--max-tokens N` (quick smoke), `--cases a,b` (subset),
`--out FILE` (apus outputs are saved; re-classify without re-running via
`--offline FILE`), `--verbose` (see engine output).

## 7. What the results mean

| Verdict | Meaning | Action |
|---|---|---|
| `identical` | Token-for-token equal. Perfect. | — |
| `near_tie_flip` | First difference at a position where the reference's top1−top2 margin was **< 0.5 logits** — a coin-flip token that flipped because GPU (CUDA/bf16) and Mac (NEON/fp32) accumulate in different orders. Expected occasionally; the M5 gate saw the same class at the same threshold. | Count them. A handful across the battery is acceptable. Streams are only compared up to the first flip (after that the contexts differ). |
| `rng_divergence` | Sampled case only. The reference draws from torch's RNG (Gumbel-max); apus draws from its own splitmix64 sampler. The streams cannot match by construction, so a flip is expected and **not** a failure. Greedy cases are the real test. | Informational. |
| `hard_mismatch` | Greedy tokens differ at a position where the reference was confident (margin ≥ 0.5). **This is a real bug.** | Stop. The report prints the position, both token ids, and the margin — file it and do not sign off R1. |
| `error` | apus run failed (engine died, timeout). | Investigate; treated as failure. |

**Exit code: 0 iff there are no hard mismatches and no errors.** Near-tie
flips and rng divergences still exit 0 and are listed in the summary.

If everything passes: R1 is closed — apus's output is token-identical (modulo
near-tie coin flips) to DeepSeek's official reference on all 8 cases, and
`docs/STATUS.md` can mark the risk resolved.

## 8. Troubleshooting

- **`torchrun` NCCL errors / hangs:** make sure you launched with
  `torchrun --nproc-per-node 4` (plain `python` only works for
  `--world-size 1`, which won't fit on one GPU). On some images you need
  `pip install nvidia-nccl-cu12`.
- **CUDA OOM during load:** the script sets
  `expandable_segments:True` like the reference. If a shard still doesn't
  fit, you're not on 80 GB cards.
- **`tilelang` install fails:** it needs a CUDA toolchain on the image
  (`nvcc`). Pick an image that has one, or `apt install cuda-toolkit-12-*`.
- **A case fails on the host:** check its `"error"` field in
  `r1_goldens.json`; compare.py skips failed golden cases (and says so).
  Re-run just that case with `--cases <id>` and re-merge by hand if needed.
- **compare.py seems stuck:** apus decode is slow (seconds per token);
  progress prints every 16 tokens. `--verbose` shows the engine's own stats.
  The per-read timeout is 30 min (`--timeout`).
