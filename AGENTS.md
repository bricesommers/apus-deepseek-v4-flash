# apus — guide for AI coding agents

Local inference engine for **DeepSeek-V4-Flash-0731** (284B-total / 13B-active
MoE, MXFP4 experts + FP8 dense, ~160 GB of weights) running on consumer
hardware. The dev target is a **MacBook Pro, Apple M1 Pro, 32 GB unified
memory**; experts are streamed from NVMe through a RAM cache while dense
weights stay resident. Design lineage: [colibri](https://github.com/JustVugg/colibri)
(Apache-2.0), which does the same for GLM-5.2 — per-file attribution notices
are kept where colibri code is reused.

Normative references: `docs/ARCHITECTURE.md` (full design + model spec),
`docs/STATUS.md` (milestone log, measured baselines, decisions),
`HISTORY.md` (session narrative), `docs/USAGE.md` / `docs/HOWTO.md` (running
the engine). Read `docs/STATUS.md` first when resuming work.

## Hard invariants (do not violate without explicit user approval)

- **Never silently change the numeric precision of any tensor or computation.**
  Dense FP8 precision is locked by user decision.
- **Never change router semantics** (sqrtsoftplus scoring, noaux_tc bias,
  top-k, scaling, hash-routing tables).
- **Expert weights are stored and computed from the original MXFP4 + UE8M0
  representation.** No transcoding to int4/int8 "for convenience".
- **Quality invariance is bitwise**: tiering, caching, prefetch, threading,
  speculative decoding and backend changes must produce bitwise-identical
  tokens. Every performance milestone so far shipped with bitwise equality
  proofs; where a documented reorder class was accepted (e.g. BLAS dispatch
  at M ≥ 256, wo_a SIMD reorder), it is recorded in the relevant
  `tests/*/README.md` and never leaks below the gate cutoffs.
- Numerics normative reference is `reference/inference/kernel.py` +
  `model.py` (they win over the tech report wherever they disagree).

## Technology stack

- **Engine: C11**, no dependencies beyond libc/pthreads (+ Accelerate on
  macOS for batch-M BLAS dispatch, + Metal/Foundation frameworks for the
  optional GPU backend). Single-binary build: `c/apus.c` is the only .c
  file; all implementation TUs are single-header libraries in `c/*.h`
  instantiated via `#define APUS_*_IMPLEMENTATION` at the top of
  `c/apus.c`.
- **Metal backend**: `c/backend_metal.mm` (Objective-C++, C++17), macOS-only,
  FP32 shaders with fast math OFF, zero-copy unified-memory buffers.
  Strictly additive — `bin/apus` (CPU) is the default and behaviorally
  untouched by Metal work.
- **Python tooling** (`tools/`): `server.py` and `chat.py` are **stdlib-only**
  by design. `convert.py`, `download.py`, oracles and test generators use
  the local `.venv` (numpy, safetensors, tokenizers 0.23.1,
  huggingface_hub — see `.venv`; there is no requirements file).
- NEON is the primary SIMD path (Apple Silicon); AVX2/FMA kernels
  (`c/x86.h`, runtime-dispatched, bitwise-equal to scalar anchors) are the
  x86_64 port. A scalar reference implementation exists first for every
  kernel and SIMD paths are proven against it.

## Build and test commands

Everything goes through the root `Makefile` (clang on macOS, gcc on Linux;
`-std=c11 -O2 -Wall -Wextra`; Linux adds `-D_GNU_SOURCE -ffp-contract=off
-fno-tree-vectorize -fno-tree-slp-vectorize` — the last two are a Rosetta
emulation workaround, proven numerics-noop; do not remove them).

```bash
make apus                 # builds bin/apus (CPU engine CLI)
make metal=1 apus         # builds bin/apus_metal (macOS only)
make test-m3              # build + regenerate goldens + run one milestone suite
make ubsan-m3             # UBSan-only variant of the same suite
make bench-m3             # benchmarks where they exist (m3, m6a, m9*, m12a2, m7b)
```

- Milestone targets: `test-m2, m3, m4a, m4c, m5, m6a, m6b, m6c, m7a, m7b
  (macOS only), m8, m9a–m9e, m11b, m12a2`, plus `check-m11a` (numpy oracle).
  `tests/m1` is a Python unittest suite (`cd tests/m1 && python3 -m unittest
  discover -s .`), not a make target.
- The Makefile uses `.venv/bin/python` by default; CI and Docker pass
  `PY=python3`.
- **ASan is broken on this Mac** (Apple clang runtime livelock in dyld init,
  pre-existing environment bug). Use the `ubsan-*` targets + `leaks` instead.
  Sanitizer flags override CFLAGS, so the UBSan recipes re-add `-ffp-contract=off`
  where numerics matter — keep that when adding new sanitizer targets.
- Many suites diff stdout across `APUS_THREADS=1/4/8` (thread-count
  independence digest). This is a hard gate — threaded paths must be
  bitwise-equal to single-threaded ones.
- Fixture/golden dirs (`tests/*/fixtures`, `tests/*/golden`) are gitignored
  and regenerated deterministically by the `golden-*` make dependencies;
  never commit them.
- Full Linux/x86_64 battery from macOS: `tools/docker/test-linux.sh`
  (linux/amd64 under emulation, ~10 min; mounts the repo read-only and builds
  in-container so Mach-O/ELF artifacts never mix). CI
  (`.github/workflows/ci.yml`) runs the same battery on ubuntu-latest +
  macos-latest (the macOS job adds the Metal suite `test-m7b`) on pushes to
  `main`. There is deliberately no Windows support (pthreads + POSIX file
  I/O; shims cover macOS and Linux only).

## Code style and conventions

- C11, `-Wall -Wextra` clean, header-only libraries with an
  `APUS_<NAME>_IMPLEMENTATION` guard; `c/apus.c` is the single TU that
  defines them all (test binaries define only what they need).
- Every header opens with a banner comment stating its **numerics contract**
  (storage layout, rounding rules, summation order, normative reference
  line numbers). When you change numerics, update that contract and the
  relevant `tests/*/README.md`.
- Comments and docs are dense, lowercase-ish, evidence-driven; measured
  numbers (not aspirations) go into READMEs and `docs/STATUS.md`. Negative
  results are documented with numbers, not deleted (see `tests/m9e/README.md`).
- Determinism: RNG is splitmix64 seeded by `--seed`; identical arguments ⇒
  bit-identical runs. Tests exploit this everywhere.
- Runtime knobs are `APUS_*` environment variables (e.g. `APUS_THREADS`,
  `APUS_EXPERT_CACHE_MB`, `APUS_PIN_MB`, `APUS_RSS_GUARD_MB`, `APUS_PILOT_K`,
  `APUS_METAL`, `APUS_THINKING`, `APUS_API_KEY`); defaults are documented in
  the owning header and `docs/USAGE.md`.
- Keep dependencies at zero: no new libraries in the C engine, no new Python
  deps for stdlib-only tools. GPU/BLAS backends stay optional and additive.
- Make minimal, gate-safe changes: the test battery pins bitwise digests
  across milestones, so an innocent-looking "cleanup" in a kernel will turn
  unrelated suites red. When a bitwise change is genuinely intended, it is a
  numerics renegotiation — a user decision, not an assumption.

## Milestone / verification workflow

- Work proceeds in numbered milestones (M0–M12 done) with hard gates: gate 2
  was kernel-numerics approval, gate 3 is the router/precision invariant
  above. Large changes are expected to land with: a new `tests/mXX/` suite
  (C tests + Python goldens + README with evidence), `test-mXX` /
  `ubsan-mXX` / `bench-mXX` Makefile targets, and a `docs/STATUS.md` entry.
- After any engine change, re-run the affected suites **and** the regression
  battery; cross-milestone digests (m6c/m9a/m9b/m9c) must stay byte-identical
  unless the change deliberately renegotiates numerics.
- Real-model smoke tests (`weights/apus-0731`, e.g. the "capital of France"
  greedy prompt) complement fixtures; expected outputs/timings are recorded
  in `docs/STATUS.md`.

## Git and release process

- Local branch `master` is the **private** working history — **never push it**.
  Public releases are manual snapshot commits on the orphan branch
  `public-release`, pushed as `main` to GitHub
  (`git push github public-release:main`; never `--all`/`--mirror`). The
  full runbook is `docs/RELEASE.md`; the snapshot recipe is in
  `tests/m12/README.md` (M12b section).
- Public license: PolyForm Noncommercial 1.0.0 for apus code; colibri parts
  Apache-2.0 and DeepSeek model/code MIT, attributed in NOTICE and per-file
  headers — preserve those headers when editing reused files.
- `.gitignore` excludes `weights/`, `.venv/`, `bin/`, `tests/*/bin`,
  `tests/*/fixtures|golden|tmp`, `*.o`, `__pycache__/`. Do not commit
  generated artifacts or weights.

## Security considerations

- The engine is local-only by design; nothing leaves the machine at runtime.
- `tools/server.py` binds an HTTP port; optional Bearer auth via
  `APUS_API_KEY`. It is single-engine FIFO (one client at a time), not
  hardened for untrusted multi-tenant exposure.
- The C engine parses untrusted-ish input (safetensors headers, tokenizer
  JSON, chat messages) — `c/st.h`/`c/json.h` are hardened parsers; preserve
  their bounds checks and keep new parsers equally defensive (this codebase
  has already caught real heap overflows with its UBSan + digest discipline).
